# 更新记录维护

[changelog.md](changelog.md) 是 GTOCore 的长期更新记录，GTOCore 与所有 fork 模组、 submodule 的同一项变化合并记录。新增功能、调整行为、移除内容、性能优化、修复问题或接入影响游戏体验的依赖改动时，按本文同步维护。

## 更新时机

- 在实现过程中，一项变化落地后就更新当前周条目，不等提交、推送、发版或用户再次提醒。
- 同一任务后续调整了实现或撤回了改动，要立即修订对应条目，使记录反映最终保留的行为。
- 收尾时对照本次实际 diff 检查遗漏和过时描述；只记录已经实现的变化，不把计划、调查结果或尚未完成的工作写成成果。
- 纯文档、格式化、仅补测试以及不改变行为的代码搬迁不单独记入更新记录。

## 周次与格式

- 按北京时间（UTC+8）的周一至周日归周，以实际完成日期确定当前周；历史条目纠错则修改原周。
- 最新一周置顶，使用完整年份的标题：`## YYYY-MM-DD—YYYY-MM-DD`。跨年时两端使用各自年份。
- 当周标题始终覆盖完整自然周，内容持续累积；没有当周章节时在开头新建，不为每次任务另起一份周报。
- 每周保留“新增”“修改与移除”“修复”三组；没有内容的组写 `- 无。`，有实际条目后替换。

```markdown
## YYYY-MM-DD—YYYY-MM-DD

**新增：**

- 物品：……
- 方块：……
- 机器：……
- 机制：……

**修改与移除：**

- ……

**修复：**

- ……
```

## 条目写法

- 用中文说明具体内容与实际效果，按需使用物品、方块、机器、配方、机制、界面等分类；不机械添加没有内容的分类。
- 同周同一功能持续调整时修改或合并原条目，避免按任务、仓库或子模块重复罗列；跨周的后续调整记入完成当周。
- 已有机器补全功能、改名或替换实现，应明确原有设备发生了什么变化，不把注册兼容、代码迁移或重构误写成全新内容。
- 配方、容量、难度规则等行为发生变化时写清变化与适用条件；开发环境专属功能注明适用范围。
- 新增功能在同周完善后保留一条完整描述；同周新增后又全部撤回的内容删除条目。对之前周次已有内容的移除或修复记录在当前周。
- 正文只保留更新内容，不附核对提交号、提交数量、分支名、历史重建说明、核对索引或本次执行过程；验证情况在任务回复中报告。
