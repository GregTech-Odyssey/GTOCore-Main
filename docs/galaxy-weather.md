# 星系天气

实现、同步、预报界面与天气专用 Mixin 位于 `GTOLib` 的 `com.gtolib.api.weather` 和 `com.gtolib.mixin`。Core 只保留物品、语言及命令树等内容注册与既有联动调用。与 `0.6.0` 的逐类差异及调用关系见 [维度类关系图](dimension-class-map.md#map-weather)。服务端监听由 `WeatherEvents` 接线，客户端监听由 Lib 的 `Client.init()` 注册。

每个维度的昼夜时间、分数余量与自然天气日程统一由 `LevelData` 保存到本维度 `data/gtolib_level.dat`。共享天气时钟及比邻星、巴纳德的虚拟恒星日程也在主世界的同类文件中。旧 `gtocore_galaxy_weather.dat`、`gtocore_instance_weather.dat` 和 `gtolib_dimension_clock.dat` 按需导入，新系统不再写入旧文件；已有新文件的数据优先。格式、原子保存和休眠规则见 [动态维度系统](dimensions.md#43-持久化是在原版上增补还是重写)。

天气类型由 `WeatherTypes.REGISTRY`（`GTRegistry.Str<WeatherType>`）注册；维度的相对出现权重、基础时长与对称浮动范围由 `WeatherProfiles` 定义。所有时长单位都是 tick，24000 tick 为一个游戏日。抽样允许相邻同类天气，因此它们可能连续持续多个周期；预报会合并这些相邻区间。

| 维度 | 自然天气（相对权重；基础时长 ± 浮动） |
|---|---|
| 默认维度、主世界、巴纳德 C | 晴天 70；18000 ± 6000 / 雨天 25；12000 ± 4000 / 雷暴 5；6000 ± 2000 |
| 太阳表面、比邻星及巴纳德恒星天气源 | 平静 85；24000 ± 8000 / 太阳风暴 15；6000 ± 2000 |
| 金星、附加模组提供的 `jupiter` 维度 | 晴天 10；6000 ± 2000 / 酸雨 90；18000 ± 6000 |
| 火星 | 晴天 75；18000 ± 6000 / 沙尘暴 25；12000 ± 4000 |
| 土卫六 | 晴天 60；18000 ± 6000 / 甲烷雨 35；12000 ± 4000 / 沙尘暴 5；6000 ± 2000 |
| 霜原星 | 晴天 35；12000 ± 4000 / 降雪 60；18000 ± 6000 / 雷暴 5；6000 ± 2000 |
| 水星、月球、谷神星、木卫一、木卫三、土卫二、冥王星、土星环 | 仅晴天；24000 |
| 轨道与空间站 | 仅平静；24000 |

每个维度有自己的随机状态和自然天气序列。启动时为已登记天体及其轨道生成至少未来 72000 tick 的序列，其他维度首次访问时生成，并随天气时钟滚动补齐。太阳表面无人访问时也照常演进；比邻星与巴纳德星没有可登陆的恒星维度，使用各自独立的天气源。运行调度器绑定主世界的 ILevel capability，各维度日程与太阳时保存在自己的 LevelData。卸载不会暂停天气；再次查询时沿原随机序列补齐经过的全部区间，保留恒星恢复期，结果与持续加载一致。昼夜也按保存的有效 tick 锚点补算，休眠预报使用目标维度自己的太阳时和速率，不借用主世界相位。

恒星风暴仅影响同星系有大气行星：风暴期间覆盖为晴天，结束后覆盖为 6000 tick 雷暴，然后回到已排定的自然天气。无大气天体、空间站和其他星系不受影响。预报用同一个覆盖算法合成这些区间。人工修改恒星天气会立即更新行星与现有 `SolarStormHandler` 的 AE 连接/反应堆状态。

`doWeatherCycle=false` 暂停天气时钟，显式天气修改仍生效。预报时间是查询时刻起的游戏小时偏移，不是各天体的昼夜时间；睡眠与 `/time` 不会跳过天气序列。

## 操作

- `/weather clear|rain|thunder [duration]`：仅修改命令执行维度；`/execute in <dimension> run weather ...` 也按执行维度处理。雨天会映射为本维度的降水类型，太阳上的雨/雷暴映射为太阳风暴。不支持的类型会报错，不会为水星或空间站添加降水。恒星覆盖期间可以设置本地自然天气，但指令会告知当前实际天气仍由恒星强制决定。
- `/gtocore weather <type> [duration]`：指定已注册的本维度天气，例如 `acid_rain`、`dust_storm`、`solar_storm`。时长使用原版时间参数（`t`、`s`、`d`）；省略时按本维度时长及浮动抽样。
- 睡眠清天气只修改睡眠所在维度，仍受恒星覆盖约束。
- 天气预报仪 `gtocore:weather_forecaster`：右键打开 GTCEu UIPro 窗口，顶部标签切换队伍已解锁的所有星球（跨星系），默认查看当前维度；在轨道或其他维度使用时也保留当前维度标签。上方状态栏以文字显示当前天气、下一天气、距变化时间与天气循环状态，下方天气条从现在延伸到未来三个游戏日（72 游戏小时），按各天气持续时间比例填入不同颜色，悬停显示天气名称与时间区间。每 3 游戏小时一格、每 12 小时一条长刻度，天气填色、刻度与昼夜标记共用双精度帧时间插值，由单调纳秒时钟连续推进并平滑校正到游戏时间；有昼夜且昼夜循环开启的维度以昼夜时钟排布刻度，日出日落线对齐到 12 小时长刻度，其余维度以天气时钟排布刻度。按实际屏幕像素覆盖率混合色块边界和刻度透明度，在条内向左滚动，绘制裁剪到边框内，天气循环暂停时填色停止移动。日出/日落使用自带的 OreUI 像素图标，以 11×11 原尺寸和默认最近邻采样显示，分别标记所选维度的日出/日落，按昼夜时钟向左移动，睡眠或 `/time` 后重新定位。太阳表面、轨道、太空、固定时间或无天空光维度不显示日出日落；关闭昼夜循环、锁定虚空时间或戴森球遮蔽恒星时也隐藏标记。下方图例只显示该维度的自然天气及恒星影响可能带来的天气。当前页每秒从服务端刷新，包含恒星风暴的实际覆盖，天气循环暂停时显示暂停。新增解锁后重新打开窗口更新标签。配方使用 MV 传感器、MV 发射器、MV 电路、时钟、钢板和数据存储棒。

昼夜周期按 [动态维度系统的独立昼夜规则](dimensions.md#24-独立昼夜时间) 缩放。三日天气预报的范围仍为 72000 服务器 tick；日出日落与昼夜刻度按目标维度的实际太阳日换算，长昼夜星球可能在整个预报范围内没有日出或日落。潮汐锁定恒星的天体隐藏昼夜标记。天气时钟、持续时间与自然日程不随昼夜倍率改变。

## 外部模组

`Level` 的天气查询、雨/雷强度查询与修改方法，以及 `ServerLevel.setWeatherParameters`、睡眠清天气方法均由 Mixin overwrite 接入 `WeatherSystem`。天气布尔查询直接返回实际天气，不等待视觉渐变，也不受原版 skylight 限制。外部模组调用 `setWeatherParameters` 或 `Level` 强度 setter 只允许修改主世界；原版天气命令通过专用本维度入口执行。直接读写 `ServerLevelData` 的原版天气字段不再影响系统，因此 Botania 晴天娃娃直接写天气数据也不会改变天气。

Ars Nouveau 的 Cloudshaper 天气仪式在非主世界直接结束。Sunrise 与 Moonfall 仪式只更改所在维度时间，不会跳过天气序列；其原版时间包转换为带本维度速率与余量的时间包。其他维度的天气 API 调用会被忽略；显式调用主世界 API 则只能修改主世界。

原版天气初始化、随机循环、逐 tick 强度更新和周期天气广播已经停用，系统不再读写或轮询 `ServerLevelData` 天气。服务端每 tick 只推进天气时钟，到自然天气边界、恒星风暴结束后的恢复边界或人工修改时才重新计算各维度状态；没有逐 tick 写回或同步。两端按切换时刻和当前游戏时间按需计算每 tick 0.01 的雨/雷渐变。天气变化、登录、切维度和重生时才发送 GTO 天气包，包含注册表 `streamCodec()` 整数 ID 和两项初始强度；原版客户端天气包不能覆盖系统状态。存盘使用 `WeatherDataIO.WEATHER` 将天气编码为稳定字符串 key，旧存档中原版天气字段不再用于初始化自然序列。酸雨与甲烷雨使用降雨表现，降雪强制使用雪的表现，并允许在原本无降水的天体群系渲染；沙尘暴使用户外尘粒与沙色雾，太阳风暴沿用已有特效。这里没有额外引入腐蚀伤害或雨水流体。

## 现实参考与游戏化取舍

火星沙尘暴、土卫六甲烷雨及沙尘暴参考 [NASA 太阳系风暴综述](https://science.nasa.gov/solar-system/10-things-tour-of-storms-across-the-solar-system/)与 [NASA 土卫六资料](https://science.nasa.gov/saturn/moons/titan/facts/)。金星硫酸云参考 [NASA 金星资料](https://science.nasa.gov/venus/venus-facts/)。木星的酸雨按本任务的游戏设定保留；实际木星云层以氨、水等为主（[NASA GISS 云微物理研究](https://www.giss.nasa.gov/pubs/abs/ro01300e.html)）。恒星风暴让行星转晴、随后雷暴是任务指定的玩法。
