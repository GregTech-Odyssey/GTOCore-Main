# 任务书热加载与热修改（开发环境）

开发环境（`runClient` / `runServer` / `runData`）下，Gradle 把源码根目录和编译 classpath 写进 `build/quest-hotreload/classpath.txt`，并通过系统属性 `gtocore.questHotReload` 交给游戏。正式包没有这个属性，以下功能全部不启用。

**正式环境不得加载热修改的类**：`QuestHot`、`QuestSource`、`QuestEdits`、`QuestItemSyntax`、`QuestHotReload` 引用了 javac 语法树（`com.sun.source`，属于 `jdk.compiler` 模块），玩家用 JRE 时没有这个模块，类一加载就抛 `NoClassDefFoundError`，方法里的启用判断拦不住（字节码校验先于执行）。是否启用只读 `QuestHotConfig`（不引用 `jdk.compiler`），所有从热修改包外进来的入口（含 GTOLib 任务书界面里的 `QuestEditor.available()`）都先判断 `QuestHotConfig.enabled()`，再调用上面这些类。

## 统一入口

- `com.gtocore.common.quest.hot.QuestHot`：热修改的唯一入口。所有对章节源码的改动（移动、标题/副标题/描述、数量、开关、依赖、新建、复制、删除、撤销重做）都先变成一条操作，按语法树定位、只改对应的几个字符。
- `QuestEditQueue`：全局操作表。坐标、文字、开关、数量、依赖这几类操作提交时直接改内存里的任务书（GTOLib `QuestLive`），画面立刻变化；源码写回在停手 1.5 秒后于后台进行，只做编译校验、不重建任务书，所以不会卡。增删目标/奖励、新建、复制、删除这类改变全书编号的操作写回后需要重建，重建在服务端线程异步完成，客户端只做约几十毫秒的收尾。同一对象的同类操作自动去重，新建后又删除直接抵消。操作表存到 `run/quest-edit-journal.json`，游戏崩溃后下次进标题画面自动重放（重放走重建）。写入或编译失败的一批会还原源码、按源码重建，并在聊天栏说明原因。
- `com.gtocore.client.QuestHotReload`：热加载实现。监听 `src/main/java/com/gtocore/data/quest/**`，或接收操作表提交的文件，游戏内只编译改动文件；需要重建时用新类加载器重跑章节定义，按存盘键迁移进度，打开着的任务书原地换成新内容。只支持单人游戏（未开放局域网）。
- `QuestHotProgress`：进度令牌。操作表自己的写入是后台任务，任务书编辑模式下只在顶部状态条显示"正在写入源码"和一条进度线，其它界面在右上角显示进度条，不影响操作；源码被外部手动修改时，先把操作表里未写入的操作写进源码，再热加载，期间全屏锁定。
- 区分自己的写入和外部修改：操作表在写文件之前先把要写入的内容登记给源码监听（`QuestHot.writing`），监听只把内容与登记不一致的变化当作外部修改。登记必须在写文件之前；放在之后时，监听 0.3 秒后就来检查，会先一步把自己的写入判成外部修改，于是每次写回后都全屏锁定并重建一次。
- `QuestSource`：章节源码的语法模型，对外是一份不可变快照。界面线程读模型只取这份快照，不碰磁盘、不解析；扫描目录、比对文件时间和重新解析只在操作表的后台线程做（每次写回前后各一次，源码监听收到文件变化时一次），解析完整体换成新快照。新增读源码模型的代码一律走 `QuestHot`，不要在界面线程调 `QuestSource.refresh`。
- 游戏内调 javac 要显式收窄路径：javac 每建一个任务都会沿类路径找编译器插件，游戏的类路径有两百多项。`QuestSource` 只做解析，文件管理器的类路径设为空；`QuestHotReload` 要用类路径做编译，把注解处理器路径设为空。不设时解析一个章节文件要半秒到一秒多，设了以后是几毫秒到十几毫秒。
- 操作表落盘（`run/quest-edit-journal.json`）同样在后台线程，多次提交合并成一次写入，游戏退出时补写一次。
- 后台线程上的写回、还原、编译任何一步抛出异常都会记日志并在聊天栏报告，本批修改留在操作表里，不会让之后的写回停摆。
- 撤销遇到已经写入源码的删除时跳过这一步并提示，可以继续撤销更早的修改；删除本身只能在 VS Code 里还原。
- 进入编辑模式时在后台预热一次编译器（解析并分析一个最小的章节文件），第一次写回不再多等几秒。

## 编辑模式操作

任务书工具栏的"编"按钮进入编辑模式：

- 左键拖动任务：移动（选中多个时一起移动），与其它任务对齐时显示对齐线，状态条显示目标坐标；左键拖空白处：框选；按住 Shift 或 Ctrl 单击、框选为加选或减选。
- 右键从前置任务拖到后续任务：增删依赖。拖动中目标任务被框出，连线带箭头指向后续任务，颜色和状态条文字说明松开后的结果：蓝色为添加依赖，红色为移除依赖或不允许（附原因，如会成环、违反主线规则）。
- 顶部状态条：第一行是模式、已选数量和写回状态（待写入、正在写入，写完后显示几秒"已写入源码"），第二行是当前操作的提示或上一次操作的结果。全部操作一览在右侧工具条的说明按钮里（编辑模式下显示编辑操作）。编辑模式下任务的悬停提示末行是任务键与坐标。
- 需要在画布上选取任务时（添加前置或后续、设为主线、任务链接、放置复制节点）：本任务被框出，悬停的候选任务显示连线和结果预览；左键单击确定，右键或 Esc 取消并回到编辑窗口。添加前置或后续可以连续点多个任务，右键或 Esc 结束；已经是前置或后续的任务不能再选，移除走编辑窗口列表里的 × 或画布上的右键拖线。不允许的候选点了不会退出选取。
- 双击或中键单击任务：打开统一编辑窗口，一页里改完所有内容：
  - 标题、副标题、描述是所见即所得的编辑区：直接按游戏里的样子显示，选中文字后点颜色或 B/I/U/S（也可 Ctrl+B/I/U）立即生效；可加任务链接、网址，描述里可插入物品（物品选择器）和分页；Enter 换段，空段就是空行；Tab 切换编辑区，编辑区里 Ctrl+Z / Ctrl+Shift+Z 撤销重做打字。
  - 目标与奖励：点"+ 添加目标/奖励"先选类型，再按类型给值，添加后立即写回并重建。
    - 目标类型：物品、物品标签、多个物品任选、确认完成、科技节点、到达维度、击杀生物、统计数值、找到结构、观察方块、难度档位、模组已安装。
    - 奖励类型：物品、带数据的物品（从背包选，保留附魔等数据）、经验等级、经验值、命令、奖励表（抽取、可落空的抽取、全部发放、自选）。
    - 给值方式：物品类走物品选择器（多个物品任选可连选，观察方块只列方块）；标签、科技节点、维度、生物、统计项、结构、难度、模组、奖励表走列表选择器，按名称或 id 搜索；命令是一行文本；确认完成、经验等级、经验值直接添加，数值在行内改。
    - 行内操作：物品目标点图标可更换物品；带数量的目标与奖励（物品、标签、任选、击杀、统计、经验）数量框直接改；所有目标可勾"可选"，物品目标可勾"消耗"；× 移除。
    - 奖励栏列出全部奖励，含同一个 `.reward(…)` 里写的多项和各难度补贴；移除多项里的一项只删那一个参数，撤销时放回原位置。
  - 主线："设为主线任务…"后在画布上点本章主线上的一个任务，这个任务接在它后面；"移出主线"把它从主线拿掉并把前后两个主线任务接上。
  - 前置任务与后续任务：各列一栏，"添加前置任务""添加后续任务"后在画布上点选，× 移除；点任务名直接切到那个任务的编辑窗口，标题栏左侧的箭头返回上一个任务。
  - 开关、在 VS Code 打开源码、放置复制节点、删除（红色，需再点一次确认）。数量框里按上下方向键增减，按住 Shift 每次 10。

### 主线规则（编辑器强制）

主线是一条不分叉的单线，相邻主线任务之间是真依赖：后一个依赖前一个。设为主线时同时写 `.mainLine(…)` 顺序、`.milestone()`、本任务依赖上一个、下一个改为依赖本任务（不再直接依赖上一个）；移出主线时反过来，把下一个改回依赖上一个。主线任务之间只能依赖紧挨着的上一个主线任务（画布拖线、添加前置都会拦），相邻主线任务之间的依赖不能单独去掉。旁支任务照常可以挂在主线任务上，主线任务也照常保留其他前置。现有章节不追溯检查（只在编辑时强制）。
- 中键单击复制节点：编辑原任务、跳转至原任务、放置复制节点、打开源码、删除；中键单击空白处：在此新建任务（物品选择器选目标物品）、撤销、重做、立即写入、全选、取消选择。
- 物品选择器：按名称、物品 id 或 `@模组` 搜索全部物品，或切到"最近"看本次游戏里选过的物品、"背包"看身上的物品；Enter 选第一项，Tab 切换分类。
- 列表选择器（`ChoicePickerPopup`）：一行一个候选项，左侧图标、名称，右侧 id；Enter 选第一项。类型菜单和命令输入也用它。
- 两个选择器的搜索都支持拼音（装有 JustEnoughCharacters 时）：全拼、首字母都能搜到中文名，如 `tieding`、`td` 搜到铁锭。只对带中文的候选项做拼音匹配，输入里带中文时按原文匹配。
- 奖励表编辑窗口（`RewardTableWindow`）：在任务编辑窗口里点奖励表奖励的图标打开。可改标题（带样式的标题除外）、抽取次数、空奖权重；内容一行一项，可改数量和权重、移除，"+ 添加内容…"的类型与任务奖励相同（不含奖励表）。添加奖励表奖励时，列表第一行是"+ 新建奖励表…"，输入 id 后在 `QuestRewardTables` 末尾新建一张表并直接打开它。改动都写回 `QuestRewardTables.java`，写回后重建任务书。
- 鼠标侧键：后退键回到上一层，前进键重做。任务书记一份浏览历史，每一格是"章节、打开的任务详情、打开的编辑窗口"；切章节、点开任务、在编辑窗口里跳到别的任务都会记一格。后退时先取消正在进行的选取或拖动，再关掉菜单、选择器这类临时弹层，然后才按历史后退；没有历史时后退等于关掉当前的详情或编辑窗口。玩家模式下同样可用。
- 新增一种目标或奖励类型：在 `QuestKinds` 的 `TaskKind` 或 `RewardKind` 里加一个常量，登记名称、说明、输入方式、候选项来源和"值写成 Java 表达式"的办法；编辑窗口不用改。常量值的 Java 写法从登记的常量类里按值反查，查不到时标签、生物、统计项、结构退回按 id 构造的写法，科技节点、维度、奖励表报"无可用 Java 写法"。
- 画布上 Ctrl+Z 撤销、Ctrl+Shift+Z 或 Ctrl+Y 重做（撤销的是操作表里的操作）。

`/gtocorec questreload` 全量重编重载。

## 写法要求（启动即校验）

`QuestHot.validateAtStartup()` 在 `Data.commonInit` 里、任务书构建之后运行：用 javac 语法树解析全部章节文件，并与构建出的任务书逐个核对。任何一处对不上，客户端直接崩溃（崩溃报告列出每一处文件和行号），服务端直接抛异常。热加载后也会重新校验，不合规时停用编辑并在聊天栏列出问题。

- 章节：`public static final QuestChapter CHAPTER = QuestChapter.of("id", c -> …)`，写在文件第一个字段。
- 任务：`public static final Quest X = CHAPTER.quest("id", q -> q` 后接链式 `.方法(…)`；lambda 只能是表达式，不能写 `{ … }` 块体。需要按条件隐藏用 `.invisible(条件)`。
- 坐标：`.at(x, y)` 恰好一次，直接写数字（可带负号）。
- 标题、副标题、描述行的第一个参数必须是字符串字面量；描述用 `.desc(d -> d.line(…).line().page()…)` 链式写法。
- 复制节点：`public static final QuestLink X = CHAPTER.copy(目标, x, y)`，或章节装饰里的 `.link(QuestLink.of(目标, x, y))`，坐标直接写数字。
- 依赖：`dependsOn` 的每个参数是同文件字段名或 `XxxChapter.FIELD`。

## 已知限制

- 改任务 id、调整子任务或奖励顺序时，进度按存盘键规则对不上；删掉的任务进度在下次存盘时丢失。
- 新建任务时物品的 Java 写法依次取：已有任务里同物品的写法 → 物品登记类的静态字段（含按电压的机器数组）→ `TagPrefix, Material`；都找不到时拒绝新建。
- 标题和副标题只接受文字样式（`QuestStyle`），不能插入物品或流体。
- 目标与奖励的标题、图标、提示（`.title(…)`、`.icon(…)`、`.tip(…)`），奖励的发放选项（`.silent()`、`.elevated()`、`.autoClaim(…)`、`.excludeFromClaimAll()` 等），奖励表的图标与带样式的标题，删除整张奖励表，描述里的图片、目标的 NBT 匹配仍在源码里改。
- 非物品目标与奖励换一个对象（如换一个科技节点）要移除后重新添加；各难度补贴只能改数量和移除，不能在窗口里新增；观察方块的时长、难度档位的数值在源码里改。
- 统计数值的候选只列注册名与值相同的统计项（原版与本包自己的），其它模组的统计项 `StatTask` 取不到统计对象。
