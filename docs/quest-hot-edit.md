# 任务书热加载与热修改（开发环境）

开发环境（`runClient` / `runServer` / `runData`）下，Gradle 把源码根目录和编译 classpath 写进 `build/quest-hotreload/classpath.txt`，并通过系统属性 `gtocore.questHotReload` 交给游戏。正式包没有这个属性，以下功能全部不启用。

## 统一入口

- `com.gtocore.common.quest.hot.QuestHot`：热修改的唯一入口。所有对章节源码的改动（移动、标题/副标题/描述、数量、开关、依赖、新建、复制、删除、撤销重做）都先变成一条操作，按语法树定位、只改对应的几个字符。
- `QuestEditQueue`：全局操作表。坐标、文字、开关、数量、依赖这几类操作提交时直接改内存里的任务书（GTOLib `QuestLive`），画面立刻变化；源码写回在停手 1.5 秒后于后台进行，只做编译校验、不重建任务书，所以不会卡。增删目标/奖励、新建、复制、删除这类改变全书编号的操作写回后需要重建，重建在服务端线程异步完成，客户端只做约几十毫秒的收尾。同一对象的同类操作自动去重，新建后又删除直接抵消。操作表存到 `run/quest-edit-journal.json`，游戏崩溃后下次进标题画面自动重放（重放走重建）。写入或编译失败的一批会还原源码、按源码重建，并在聊天栏说明原因。
- `com.gtocore.client.QuestHotReload`：热加载实现。监听 `src/main/java/com/gtocore/data/quest/**`，或接收操作表提交的文件，游戏内只编译改动文件；需要重建时用新类加载器重跑章节定义，按存盘键迁移进度，打开着的任务书原地换成新内容。只支持单人游戏（未开放局域网）。
- `QuestHotProgress`：进度令牌。操作表自己的写入是后台任务，只在右上角（任务书里在编辑横幅下方）显示"写入代码 / 读取代码"进度条，不影响操作；源码被外部手动修改时，先把操作表里未写入的操作写进源码，再热加载，期间全屏锁定。

## 编辑模式操作

任务书工具栏的"编"按钮进入编辑模式：

- 左键拖动任务：移动（选中多个时一起移动）；左键拖空白处：框选；右键从前置任务拖到后续任务：增删依赖。
- 中键单击任务：打开统一编辑窗口，一页里改完所有内容：
  - 标题、副标题、描述是所见即所得的编辑区：直接按游戏里的样子显示，选中文字后点颜色或 B/I/U/S（也可 Ctrl+B/I/U）立即生效；可加任务链接、网址，描述里可插入物品（物品选择器）和分页；Enter 换段，空段就是空行；Tab 切换编辑区，编辑区里 Ctrl+Z / Ctrl+Shift+Z 撤销重做打字。
  - 目标与奖励：点物品图标用物品选择器更换，"+ 添加目标/奖励"从选择器选，数量框直接改，目标可勾"消耗""可选"，× 移除。
  - 主线："设为主线任务…"后在画布上点本章主线上的一个任务，这个任务接在它后面；"移出主线"把它从主线拿掉并把前后两个主线任务接上。
  - 开关、前置任务（"添加前置任务"后在画布上点选）、在 VS Code 打开源码、复制到、删除。

### 主线规则（编辑器强制）

主线是一条不分叉的单线，相邻主线任务之间是真依赖：后一个依赖前一个。设为主线时同时写 `.mainLine(…)` 顺序、`.milestone()`、本任务依赖上一个、下一个改为依赖本任务（不再直接依赖上一个）；移出主线时反过来，把下一个改回依赖上一个。主线任务之间只能依赖紧挨着的上一个主线任务（画布拖线、添加前置都会拦），相邻主线任务之间的依赖不能单独去掉。旁支任务照常可以挂在主线任务上，主线任务也照常保留其他前置。现有章节不追溯检查（只在编辑时强制）。
- 中键单击复制节点：编辑原任务、跳到原任务、复制到、打开源码、删除；中键单击空白处：在此新建任务（物品选择器选目标物品）、撤销、重做、立即写入、全选、取消选择。
- 物品选择器：按名称、物品 id 或 `@模组` 搜索全部物品，或切到"背包"只看身上的物品。
- 画布上 Ctrl+Z 撤销、Ctrl+Shift+Z 或 Ctrl+Y 重做（撤销的是操作表里的操作）。

`/gtocorec questreload` 全量重编重载。

## 写法要求（启动即校验）

`QuestHot.validateAtStartup()` 在 `Data.commonInit` 里、任务书构建之后运行：用 javac 语法树解析全部章节文件，并与构建出的任务书逐个核对。任何一处对不上，客户端直接崩溃（崩溃报告列出每一处文件和行号），服务端直接抛异常。热加载后也会重新校验，不合规时停用编辑并在聊天栏列出问题。

- 章节：`public static final QuestChapter CHAPTER = QuestChapter.of("id", c -> …)`，写在文件第一个字段。
- 任务：`public static final Quest X = CHAPTER.quest("id", q -> q` 后接链式 `.方法(…)`；lambda 只能是表达式，不能写 `{ … }` 块体。需要按条件隐藏用 `.invisible(条件)`。
- 坐标：`.at(x, y)` 恰好一次，直接写数字（可带负号）。
- 标题、副标题、描述行的第一个参数必须是字符串字面量；描述用 `.desc(d -> d.line(…).line().page()…)` 链式写法。
- 复制节点：`public static final QuestLink X = CHAPTER.copy(目标, x, y)`，或章节装饰里的 `.link(QuestLink.of(目标, x, y))`，坐标直接写数字。
- 依赖：`dependsOn` 的每个参数是同文件字段名或 `XxxChapter.FIELD`。

## 已知限制

- 改任务 id、调整子任务或奖励顺序时，进度按存盘键规则对不上；删掉的任务进度在下次存盘时丢失。
- 新建任务时物品的 Java 写法依次取：已有任务里同物品的写法 → 物品登记类的静态字段（含按电压的机器数组）→ `TagPrefix, Material`；都找不到时拒绝新建。
- 标题和副标题只接受文字样式（`QuestStyle`），不能插入物品或流体。
- 非物品目标（击杀、维度、科技节点等）、奖励表、描述里的图片、目标的 NBT 匹配与标签目标仍在源码里改；编辑窗口里非物品目标只能移除。
